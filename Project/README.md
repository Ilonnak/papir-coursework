# Вебзастосунок «папір.»

Курсова робота з дисципліни «Веб-технології та веб-дизайн».

Тема: «Каталог канцелярських товарів із керуванням пропозиціями та оформленням замовлень».

Виконала: Куриленко Ілона Олександрівна, група АІ-244.

## 1. Призначення

Застосунок призначений для перегляду канцелярських товарів, керування товарними пропозиціями та оформлення замовлень.

Покупець може:

- переглядати каталог і детальну інформацію про товари;
- виконувати пошук, фільтрацію та сортування;
- реєструватися й входити до облікового запису;
- додавати товари до кошика, змінювати кількість і видаляти позиції;
- оформлювати замовлення;
- переглядати власні замовлення та їхні статуси.

Адміністратор може:

- створювати й редагувати товари та категорії;
- змінювати характеристики, ціни та залишки;
- завантажувати зображення;
- приховувати товари з публічного каталогу;
- переглядати та обробляти замовлення;
- фіксувати оплату при отриманні;
- завершувати або скасовувати замовлення за встановленими правилами.

Отримання замовлень здійснюється через навчальний пункт самовивозу. Застосунок зберігає факт отримання оплати, але не проводить банківські платежі.

## 2. Використані технології

- Клієнтська частина: Vue 3, Vue Router, Pinia, Vite.
- Серверна частина: C#, ASP.NET Core Web API, .NET 8.
- Робота з даними: Entity Framework Core, Npgsql.
- База даних: PostgreSQL.
- Автентифікація: JWT.
- Інтеграційне тестування: xUnit.

Застосунок складається з окремих клієнтської та серверної частин. Клієнт надсилає HTTP-запити до API, сервер виконує перевірки й працює з PostgreSQL.

## 3. Необхідне програмне забезпечення

Інструкція розрахована на локальний запуск у Windows.

Потрібно встановити:

- .NET 8 SDK для збирання та запуску сервера;
- Node.js із npm для встановлення залежностей і запуску клієнта;
- PostgreSQL 16 для збереження даних;
- веббраузер.

Для керування PostgreSQL можна використовувати pgAdmin.

Перевірте доступність команд у PowerShell:

```powershell
dotnet --info
node --version
npm --version
```

Якщо команда не розпізнається, перевірте встановлення відповідної програми. Після встановлення відкрийте нове вікно PowerShell.

Служба PostgreSQL має бути запущена.

Для першого встановлення залежностей потрібен доступ до інтернету.

## 4. Структура комплекту

Комплект містить папки Project та Diagrams.

У Diagrams розташовані діаграми архітектури, бази даних, прецедентів та основних алгоритмів.

У Project розташовані:

| Шлях | Призначення |
|---|---|
| frontend/src | Сторінки, компоненти, клієнтські сховища та робота з API |
| frontend/package.json | Перелік клієнтських залежностей і команд |
| frontend/package-lock.json | Зафіксовані версії клієнтських залежностей |
| backend/Controllers | Обробка HTTP-запитів |
| backend/Services | Бізнес-логіка застосунку |
| backend/Models | Моделі даних |
| backend/DTOs | Об’єкти передавання даних |
| backend/Data/AppDbContext.cs | Налаштування роботи Entity Framework Core з базою |
| backend/Database | SQL-скрипти створення й оновлення схеми |
| backend/wwwroot | Зображення та інші статичні файли |
| backend/appsettings.example.json | Шаблон конфігурації |
| backend.tests | Інтеграційні тести |
| CourseworkApp.slnx | Файл рішення |
| start.ps1 | Запуск клієнта й сервера у Windows |
| stop.ps1 | Зупинка процесів, запущених скриптом |
| test-results.txt | Журнал тестового прогону від 08.11.2026 |

Для команд із цієї інструкції відкривати файл рішення не потрібно: сервер і тести запускаються через відповідні файли .csproj.

Каталоги node_modules, bin та obj не включені до архіву. Вони створюються під час встановлення залежностей і збирання.

## 5. Звідки виконувати команди

Розпакуйте архів. Відкрийте папку Project, у якій знаходяться backend, frontend, README.md і start.ps1.

Щоб відкрити PowerShell у цій папці:

1. Відкрийте Project у Провіднику Windows.
2. Натисніть адресний рядок.
3. Введіть powershell.
4. Натисніть Enter.

Перевірте поточну папку:

```powershell
Get-Location
Get-ChildItem
```

У переліку мають бути backend, frontend і start.ps1.

Якщо не зазначено інше, всі наступні команди виконуються саме з Project.

Позначення `.\` у команді означає поточну папку. Наприклад, `.\backend\Backend.csproj` – це файл Backend.csproj у вкладеній папці backend.

## 6. Налаштування конфігурації

Робочий файл appsettings.json до архіву не включений. Створіть його на основі шаблону:

```powershell
Copy-Item .\backend\appsettings.example.json .\backend\appsettings.json
```

Відкрийте створений файл:

```powershell
notepad .\backend\appsettings.json
```

Якщо робоча конфігурація вже існує, повторно копіювати шаблон поверх неї не потрібно.

### 6.1 Підключення до PostgreSQL

У ConnectionStrings:DefaultConnection зазначте параметри свого сервера PostgreSQL:

```json
"DefaultConnection": "Host=localhost;Port=5432;Database=coursework_web;Username=postgres;Password=<YOUR_POSTGRES_PASSWORD>"
```

Параметри рядка:

| Параметр | Значення |
|---|---|
| Host | Адреса PostgreSQL; для локального запуску зазвичай localhost |
| Port | Порт PostgreSQL; стандартне значення 5432 |
| Database | Назва створеної бази |
| Username | Користувач PostgreSQL |
| Password | Пароль цього користувача PostgreSQL |

Замініть `<YOUR_POSTGRES_PASSWORD>` своїм паролем. Кутові дужки також потрібно прибрати.

Пароль PostgreSQL і паролі для входу на сайт – різні налаштування.

Для перевірки можна використати іншу окрему базу, наприклад coursework_web_check. Тоді її назву потрібно вказати і під час створення бази, і в параметрі Database.

### 6.2 Параметри JWT

У Jwt:Key замініть заповнювач власним випадковим ключем довжиною щонайменше 32 символи.

Цей ключ використовується сервером для підпису токенів. Він не є паролем користувача.

Issuer та Audience можна залишити такими, як у шаблоні.

### 6.3 Демонстраційні облікові записи

Розділ DemoSeed задає налаштування початкового наповнення бази.

Перед першим наповненням замініть:

- `<DEMO_ADMIN_PASSWORD>` – паролем адміністратора;
- `<DEMO_BUYER_PASSWORD>` у двох записах CustomerAccounts – паролями покупців.

Для локальної навчальної перевірки можна встановити:

- адміністратору – `AdminDemo!2026`;
- обом покупцям – `BuyerDemo!2026`.

Ці значення потрібно вписати у відповідні поля Password. Автоматично вони не встановлюються.

Залиште DemoSeed:Enabled зі значенням true.

Збережіть файл. У JSON потрібно зберегти подвійні лапки, коми та фігурні дужки.

### 6.4 Пункт самовивозу

Розділ PickupPoint містить:

- назву навчального пункту видачі;
- умовну адресу;
- графік роботи;
- інформацію про оплату.

Для демонстрації можна залишити значення з шаблону.

## 7. Створення порожньої бази

Спочатку потрібно створити саму базу PostgreSQL. Таблиці вручну створювати не потрібно.

Через pgAdmin:

1. Підключіться до свого сервера PostgreSQL.
2. Натисніть правою кнопкою на Databases.
3. Оберіть Create → Database.
4. Введіть coursework_web.
5. Збережіть.

Альтернативний спосіб – відкрити Query Tool для бази postgres і виконати:

```sql
CREATE DATABASE coursework_web;
```

Використайте один із цих способів.

Якщо база з такою назвою вже існує, повторно створювати її не потрібно. Не видаляйте наявну базу з потрібними даними.

Назва має збігатися з параметром Database у backend/appsettings.json.

## 8. Як створюються таблиці

У проєкті використовуються SQL-скрипти.

Скрипти знаходяться в backend/Database:

| Скрипт | Призначення |
|---|---|
| 000_full_schema_for_empty_db.sql | Створення базових таблиць у порожній базі |
| 001_extend_existing_schema.sql | Доповнення схеми полями та обмеженнями |
| 002_concurrency_and_idempotency.sql | Додавання полів для контролю версій товарів і повторних запитів |

Їх виконує DatabaseInitializer із папки backend/Services.

Під час запуску сервер готує схему та довідник статусів. Окреме демонстраційне наповнення додає користувачів, категорії, товари й приклади замовлень.

Для звичайного запуску за цією інструкцією вручну обирати та виконувати SQL-файли не потрібно.

Користувач PostgreSQL повинен мати права на створення таблиць та інших об’єктів у вибраній базі.

## 9. Встановлення залежностей

У PowerShell із папки Project виконайте:

```powershell
dotnet restore .\backend\Backend.csproj
```

Команда завантажує NuGet-пакети серверного проєкту. Товари до бази вона не додає.

Після успішного завершення виконайте:

```powershell
npm --prefix .\frontend ci
```

Команда встановлює клієнтські залежності за package-lock.json. Дані до PostgreSQL вона також не додає.

Дочекайтеся завершення кожної команди. Якщо виникла помилка, усуньте її перед наступним кроком.

## 10. Демонстраційне наповнення

Для першого запуску на новій базі виконайте з Project:

```powershell
dotnet run --project .\backend\Backend.csproj -- --seed-demo --seed-only
```

Значення параметрів:

- `dotnet run --project` – зібрати та запустити зазначений серверний проєкт;
- `--` – передати наступні параметри самому застосунку;
- `--seed-demo` – явно запустити демонстраційне наповнення;
- `--seed-only` – завершити програму після підготовки даних, не запускаючи вебсервер.

Після успішного виконання очікується повідомлення:

```text
Демонстраційні дані каталогу «папір.» успішно перевірено та підготовлено.
```

Повернення до запрошення PowerShell після цієї команди є нормальною поведінкою.

Наповнення створює:

- 6 категорій;
- 23 стандартні товари;
- адміністратора;
- двох покупців;
- приклади замовлень, якщо таблиця замовлень ще порожня.

Один стандартний товар прихований, тому без фільтрів у публічному каталозі очікується 22 товари.

Відомості про початкові товари містяться в backend/Services/DatabaseInitializer.cs. Файли зображень зберігаються в backend/wwwroot та включені до архіву. Завантажувати їх вручну повторно не потрібно.

Повторне наповнення не скидає базу до початкового стану. Наявні демонстраційні товари зі збереженим SeedKey не перезаписуються, а акаунти не отримують нові паролі лише через зміну конфігурації.

Для запуску на іншому комп’ютері копія робочої бази автора не потрібна. Вона потрібна лише для перенесення саме її поточного стану, зокрема додаткових змін і замовлень.

## 11. Запуск клієнта та сервера

Після налаштування й наповнення виконайте з Project:

```powershell
.\start.ps1
```

Скрипт запускає сервер і клієнт, перевіряє доступність сервісів та зберігає журнали в папці .run.

Відкрийте:

| Адреса | Призначення |
|---|---|
| http://localhost:5173 | Інтерфейс застосунку |
| http://localhost:5150/swagger | Документація API |
| http://localhost:5150/api/health | Перевірка відповіді серверного застосунку |

Для запуску порти 5150 та 5173 мають бути вільними.

Не запускайте одночасно дві копії проєкту на цих портах.

### Ручний запуск

Якщо виконання PowerShell-скриптів заборонене, відкрийте два вікна PowerShell у Project.

У першому виконайте:

```powershell
dotnet run --project .\backend\Backend.csproj
```

У другому:

```powershell
npm --prefix .\frontend run dev
```

Обидва процеси мають залишатися запущеними під час роботи із сайтом.

## 13. Основний сценарій перевірки

1. Відкрити каталог.
2. Перевірити відображення зображень, пошук, категорії та сортування.
3. Відкрити сторінку товару.
4. Увійти як покупець.
5. Додати доступний товар до кошика.
6. Змінити кількість та перевірити підсумкову суму.
7. Заповнити контакти отримувача.
8. Оформити замовлення та запам’ятати його номер.
9. Перевірити замовлення в розділі власних замовлень.
10. Вийти та увійти як адміністратор.
11. Знайти створене замовлення за номером.
12. Перевести його у статус «В обробці».
13. Зафіксувати оплату при видачі та завершити замовлення.
14. Повторно увійти як покупець і перевірити оновлений стан.

Для перевірки скасування створіть окреме неоплачене замовлення. Після його скасування адміністратором замовлена кількість повертається до залишків.

Для перевірки керування каталогом можна створити окремий товар, завантажити зображення, змінити ціну та приховати товар.

## 14. Збирання та автоматизовані тести

Перевірка збирання інтерфейсу:

```powershell
npm --prefix .\frontend run build
```

Команда створює папку frontend/dist. Для звичайного локального запуску через Vite копіювати її до backend не потрібно.

Запуск інтеграційних тестів:

```powershell
dotnet test .\backend.tests\Backend.Tests.csproj --logger "console;verbosity=normal"
```

Тести використовують PostgreSQL та окрему базу coursework_web_automated_tests.

Користувач PostgreSQL повинен мати права на створення й видалення тестової бази. Вона перестворюється тестами, тому не призначена для збереження потрібних робочих даних.

Не зазначайте coursework_web_automated_tests як робочу базу застосунку.

У test-results.txt збережено журнал прогону від 08.11.2026: 16 успішних тестів. Це історичний результат. Результат нового запуску відображається в консолі.

## 16. Можливі проблеми

### Команда не знаходить Backend.csproj

Перевірте поточну папку. Команди з цієї інструкції виконуються з Project.

Якщо PowerShell уже відкритий у backend, команда наповнення має вигляд:

```powershell
dotnet run --project .\Backend.csproj -- --seed-demo --seed-only
```

### Помилка підключення до PostgreSQL

Перевірте:

- чи запущена служба PostgreSQL;
- чи створена база;
- чи збігається її назва з Database у рядку підключення;
- чи правильно зазначені Host, Port, Username і Password;
- чи має користувач потрібні права.

### Не знайдено appsettings.json

Створіть файл за шаблоном із розділу 6 і заповніть налаштування.

Переконайтеся, що файл названий appsettings.json, а не appsettings.json.txt.

### Помилка читання конфігурації

Перевірте синтаксис JSON: подвійні лапки, коми, дужки та відсутність коми після останнього поля об’єкта.

### Сайт відкривається, але товари не знайдено

Очистьте пошук і фільтри.

Якщо каталог залишається порожнім:

1. Зупиніть застосунок.
2. Перевірте підключення в backend/appsettings.json.
3. Виконайте команду наповнення з розділу 10 повністю, з обома параметрами.
4. Перевірте повідомлення про успішне завершення.
5. Знову запустіть застосунок та оновіть сторінку.

Якщо дані є в PostgreSQL, але сайт їх не показує, перевірте, чи запущений сервер саме цієї копії проєкту та чи використовує він ту саму базу.

### Зображення не відображаються

Перевірте, чи повністю розпакована папка backend/wwwroot/uploads/products.

Не перейменовуйте файли зображень без відповідної зміни посилань на них у даних.

Інтерфейс має відкриватися через запущений клієнт на http://localhost:5173. Відкриття index.html подвійним натисканням не замінює запуск застосунку.

### Не вдається увійти

Перевірте:

- чи виконано демонстраційне наповнення;
- чи правильно введено email;
- чи використовується пароль, заданий перед створенням акаунта;
- чи сервер підключений до потрібної бази.

### Порт 5150 або 5173 зайнятий

Зупиніть попередню копію застосунку. Скрипт запуску не завершує сторонні процеси автоматично.

### Не знайдені клієнтські залежності

Виконайте з Project:

```powershell
npm --prefix .\frontend ci
```

### Тести не можуть створити базу

Перевірте права користувача PostgreSQL на створення баз даних та доступність сервера. Для тестів використовується окрема база coursework_web_automated_tests.
